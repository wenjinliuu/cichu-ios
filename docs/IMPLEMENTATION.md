## 数据与行为约定

- `Place` 使用稳定 UUID；归档保留历史关联。
- `JournalEntry` 区分停留与移动；移动保存起点、终点，不存连续 GPS 轨迹。
- 同一时刻最多一个未结束记录；重复进入同一地点不重复创建记录。
- 离开 A 后开启移动；到达 B 后结束移动并开启停留。暂停会结束当前记录，恢复不会把暂停空白当作移动。
- 地点范围重叠时，单次位置检测优先匹配最近的地点。实际围栏事件仍可能受系统调度影响；建议避免相邻范围重叠。
- 按日统计使用 Calendar 的实际日区间，包含跨日切片及夏令时日长差异。历史按查看设备当前时区展示，不保存每次事件的原始时区。
- 统计只累计已有记录，不填满全天。移动均值使用完整起终点事件的全程时长；跨统计边界的路线均值按包含该路线的区间展示全程值。
- 备份恢复只允许空数据库，整包验证后保存；重复 UUID、无效坐标、未知地点、时间重叠、未来时间均拒绝。未结束记录在恢复时截止到导出时间，避免补出虚假时长。
- SQLite 由 SwiftData 管理；不启用 CloudKit。采用系统应用沙盒保护，没有另加数据库密码或独立加密层。
- 示例体验完全使用独立内存容器，不申请定位、不启动后台监测。

## 自动定位的现实边界

- 最多同时监测 20 个地点，注册时优先选择离最近位置更近的地点；更多地点可手动签到和补记。
- 使用围栏和显著变化，不启用连续 GPS，也不声明持续 `UIBackgroundModes/location`。后台记录依赖“始终”位置权限和系统对区域事件的投递。
- 时间戳是应用收到事件的时间，可能晚于实际到达／离开。此版本不宣称秒级准确。
- 强制退出、重启、后台刷新关闭、权限变化、弱信号、省电及室内环境都需要真机验收。未收到离开事件时，进行中的停留可能需要用户校正。
- 数据库暂不增加自动推测中断上限，避免擅自截断真实长停留。
- 定位与持久化服务由 AppDelegate 在应用生命周期中持有，location 事件唤醒时重新注册监测；不依赖某个页面保持可见。系统唤醒、未运行时投递与重启场景仍须真机验证。
