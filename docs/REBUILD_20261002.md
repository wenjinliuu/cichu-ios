# 此处 1.1：自动停留记录与整顿

## 触发问题与修复

已设定地点内，打开 App 或点定位仍无法开始计时。原实现要求两次一致定位相隔 90 秒，并要求整个误差圆进入围栏；低功耗事件稀疏，95 秒后台任务也不能保证运行。现改为前台有效定位立即开始、系统围栏事件立即落库，系统访问地点事件补充近似到达／离开时间。识别不依赖后台定时器。

位置证据不足时不强行切换：过滤陈旧／低精度位置，当前地点使用边界滞回；重叠围栏保留当前地点并请求定位核实。新增地点或恢复前台都会定位。常用围栏最多 20 个，按距离选择，差量注册，不在每次打开时全部注销。系统发现的未命名地点不占用围栏槽位，编辑保存后成为常用地点。

访问地点事件保存在本机（最多最近 2000 条），按事件键去重。延迟的已完成访问可修补自动时间段；不覆盖手动记录；缺少到达时间时不创造开始时间；暂停前的时间不回填。前台恢复发现长时间缺少定位证据时标为待核对，不擅自截断真实长停留。移动代表两次地点事件之间的时间，不能解释为全程持续运动。

## 没有实现的后续路线

遵守 PRODUCT_PLAN：先把地点 × 时间做好。iCloud 同步、Widget／Live Activity、Screen Time、HealthKit、日历／照片关联、高级生活半径、年度故事、订阅／购买、回放视频导出仍属后续，尚未接入；不提供占位付费按钮，不声明已经支持。精确区分同一商场相邻店铺、秒级停留、无授权补回全天历史不作为功能承诺。

## 验证与发布

测试只在中央 GitHub Actions 上运行。新增 LocationServiceTests、VisitReconciliationTests、原生图像快照和关键 UI 流程。保留已有时间、数据与 TransitionGate 测试（旧防抖工具仍保留供算法对比，生产定位不再使用）。快照固定数据／视口，浅色、深色及大字体；CI 录制后提交参考图，再非录制运行确认。首次整改每次默认 full；可以手动选择 fast／ui。

TestFlight 仍支持手动／v 标签；主分支提交信息明确包含 `[release testflight]`，且该提交 Build & Test 成功，才自动发版。普通提交不会上传，工作流检查运行 SHA 与当前 main 完全相同。先核对 Apple 注册，再无签名打包验证，最后签名上传；测试复用同一提交已通过的 full 结果。所有密钥继续使用 App 仓库现有 Secrets。发布结果以 Actions 日志为准，后台定位必须真机测试，模拟器测试不能证明全天不漏记。
