# 此处 — 产品规划草案

> 内部规划文档。暂不放入 README，避免首页过早暴露完整产品路线。

## 一句话定位

**此处**是一款以“地点 × 时间”为核心的个人生活时空日志。

它不只是记录“去了哪里”，而是回答：

- 我在哪里？
- 我在那里待了多久？
- 两个地点之间花了多久？
- 我在那里时，时间是如何度过的？
- 一周、一个月、一年甚至多年后，我的生活发生在哪里？

## 核心产品原则

1. **地点是入口，时间是主角。**
2. **自动记录优先，手动操作尽量少。**
3. **本地优先、隐私优先、默认无账号。**
4. **长期使用越久，数据价值越高。**
5. **不扩张成待办、笔记、聊天或通用社交产品。**
6. 所有新功能都应服务于四个核心维度：**地点、时间、活动、记忆**。

## V1 核心

### 1. 地点停留

用户可定义：

- 家
- 公司
- 健身房
- 商场
- 咖啡店
- 其他常用地点

系统通过 Core Location 等能力，尽量低功耗识别进入与离开。

核心记录：

- 到达时间
- 离开时间
- 单次停留时长
- 当天累计时长
- 周 / 月 / 年累计时长

### 2. 今日时间地图

首页重点不是传统轨迹，而是“今天的时间去了哪里”。

示例：

- 家 9h 42m
- 公司 8h 11m
- 通勤 1h 24m
- 健身 1h 06m
- 其他 37m

同时用地图与 24 小时时间轴呈现。

### 3. 移动 / 通勤

定义：

**离开地点 A → 到达地点 B = 一次移动。**

例如：

07:42 离开家  
08:31 到达公司  
→ 本次通勤 49 分钟

后续可识别高频路线并统计：

- 家 ↔ 公司
- 家 ↔ 健身房
- 公司 ↔ 商场
- 其他常见路线

可展示单次、平均、周、月、年累计移动时间。

### 4. 长期时间维度

产品不局限于“今天”。

数据视角逐步扩展：

- 今天
- 本周
- 本月
- 今年
- 多年

长期可形成：

- 最常停留地点
- 第一次到访
- 最近一次到访
- 累计停留时长
- 历史居住地点
- 历史工作地点
- 生活半径变化
- 高频地点关系
- 年度回顾

## V1.5 / V2 候选

### Screen Time 融合

在 Apple 系统授权与隐私规则允许的范围内，引入 DeviceActivity / FamilyControls 等能力。

目标不是复制系统“屏幕使用时间”，而是把手机使用放回地点上下文中。

例如：

**家 · 19:32–23:48 · 4h16m**

- 手机使用 2h41m
- 视频 42m
- 社交 48m
- 阅读 31m

或者：

- 在家时手机使用占停留时间 41%
- 通勤时手机使用占 62%
- 健身房时手机使用占 8%

该能力需严格遵守 Apple entitlement、隐私和 App Store 审核要求。

### 日历融合

地点回答“在哪”，日历帮助解释“为什么在那”。

例如：

- 14:00–15:30 客户会议
- 地点与日历事件自动关联

### Apple Health / 运动

例如：

- 健身房停留 1h20m
- 实际锻炼 52m
- 公园停留 45m
- 步行 3.2km

### 地点记忆

某地点可逐渐形成长期记忆页：

- 去过多少次
- 累计多久
- 第一次到访
- 最近一次到访
- 最常出现的时间段
- 对应照片数量（后续评估 Photos 权限与实现）

## 传播设计

传播重点不是邀请机制，而是“结果值得分享”。

候选分享内容：

- 今日此处
- 本周时间分配
- 我的九月
- 年度此处
- 今年最常停留的地点
- 今年在公司待了多久
- 今年花了多少时间通勤
- 今年去了多少个新地点
- 生活半径变化

分享卡片保持克制，并带轻量品牌标识：

**此处 · 时间都去了哪里**

## 商业模式方向

初期倾向：

1. 免费下载
2. 核心功能免费
3. 此处 Pro：一次性永久买断
4. 若未来出现持续云端 / AI 成本，再增加可选的“此处+”订阅

初步思路：

- Free：基础地点、今日、近 7 天、基础统计
- Pro：无限地点、完整历史、周/月/年、高级统计、自定义、导出、组件等
- 此处+：未来真正产生持续成本的云同步、AI 周报、多设备等

原则：

- 不用广告破坏产品质感
- 不把永久 Pro 已有功能收回改订阅
- 订阅只承载持续提供的新服务

## 技术方向

优先考虑：

- SwiftUI
- MapKit
- Core Location
- SwiftData
- 本地优先存储

后续按实际能力评估：

- DeviceActivity
- FamilyControls
- ManagedSettings
- HealthKit
- EventKit
- Photos

## 隐私原则

这是产品的核心竞争力之一。

默认方向：

- 无账号
- 无后端依赖
- 地点与生活轨迹尽量只保存在设备本地
- 明确说明每项权限用途
- 尽量不上传原始定位历史
- 后续若增加同步，优先考虑 Apple 生态内的隐私友好方案

## 开发与发布路径

当前开发条件：无本地 Mac。

建议链路：

GitHub  
→ GitHub Actions / macOS runner  
→ CI 编译与测试  
→ 手动触发 Beta 构建  
→ App Store Connect  
→ TestFlight 真机测试

建议拆成两条 workflow：

### CI

普通提交触发：

- 编译
- 单元测试
- 静态检查（后续）

不进行签名与 TestFlight 上传。

### Beta

手动触发：

- Archive
- 签名
- 导出
- 上传 TestFlight

定位、后台运行、锁屏、长时间驻留等核心能力必须依赖真机长期测试。

## 暂不做

为了防止产品失焦，暂不考虑：

- 通用待办
- 通用笔记
- 聊天
- 普通社交 feed
- 记账
- 与“地点 × 时间”无关的效率功能
